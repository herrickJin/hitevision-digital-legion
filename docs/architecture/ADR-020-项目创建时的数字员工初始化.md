# ADR-020：项目创建时的数字员工初始化

## 上下文

项目负责人创建项目后需要引入数字员工。有两种入口：从组织市场浏览申请（ADR-019），或在创建项目时直接选择。需要确定项目创建时的数字员工初始化方式。

## 决策

**项目创建最后一步展示可用 Soul 原型列表，项目负责人勾选，系统批量创建实例申请。可跳过，后续再申请。**

### 项目创建完整流程

```
1. 填写项目基础信息
   - 项目名称（必填）
   - 项目目标 Objective（必填）
   - 项目负责人 Owner（必填）
   ↓
2. 邀请项目成员
   - 选择组织成员，分配项目角色（Member / Viewer）
   - 可跳过，后续再邀请
   ↓
3. 绑定 Wiki
   - 选择组织 Wiki 文档集
   - 可跳过，后续再绑定
   ↓
4. 选择数字员工（可跳过）
   - 展示组织市场上架的 Soul 原型列表
   - 项目负责人勾选需要的数字员工
   - 展示每个原型的简要信息和风险等级
   ↓
5. 创建项目
   - 状态：筹备中
   - 选中的数字员工自动进入实例申请流程
   - 低风险原型自动通过，高风险走审批
   ↓
6. 项目进入筹备中状态
   - 等待 P0 必备项全部满足后可启动
   - （项目名称、Owner、目标、成员、配额、实例池、知识绑定）
```

### 批量申请行为

- 勾选多个原型时，每个原型生成独立的实例申请单
- 低风险原型自动通过并派发
- 高风险原型进入审批流程，不阻塞其他实例
- 申请结果通过通知服务告知项目负责人

## 被拒绝的替代方案

1. **按项目模板预置**——选择项目模板（如"全栈产品项目"），模板定义默认数字员工。被拒绝因为 Phase 1 需要先建模板体系，增加概念数量。

2. **按组织默认配置预置**——组织管理员定义每个新项目的默认数字员工。被拒绝因为 Phase 1 组织治理还很简单，不支持这种配置。

## 后果

### 正面

- 项目创建时一步到位配置数字员工，减少后续操作步骤
- 可跳过设计不强制用户——后续可以随时从市场申请
- 复用现有实例申请流程（批量快捷入口），不需要新机制

### 负色

- 项目创建流程步骤较多（5 步），可能影响创建体验。缓解：步骤 2/3/4 都可跳过，最简只需步骤 1+5

## 复审条件

- 当需要引入项目模板时
- 当创建流程步骤过多影响体验时
