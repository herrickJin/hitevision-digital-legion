# ADR-013：跨状态机联动规则

## 上下文

数字军团OS 定义了四套独立的状态机：Soul 原型（8态）、实例（7态）、Issue（7态）、Project（4态）。这些状态机之间存在跨机影响，但 PRD 没有显式定义所有联动规则。

## 决策

### 完整联动矩阵

| 触发事件 | 影响范围 | 联动行为 |
|----------|----------|----------|
| Soul 原型归档 | 所有关联实例 | 关联实例全部进入回收流程 |
| Soul 原型发布 Major 更新 | 使用旧版本的实例 | 通知确认，不阻断使用。创建新 Issue 时提示"有待确认更新" |
| Project 归档 | 项目内所有实例 + Issue | 实例全部回收，Issue 数据保留只读 |
| Project 暂停 | 项目内所有实例 + Issue | 实例停止运行，Issue 不可创建 |
| Project 恢复 | 项目内实例 | 实例可重启，Issue 可创建（需配额未超限） |
| 实例停止 | 该实例上运行中的 Issue | 运行中 Issue 强制标记为"执行失败"，原因为"实例已停止" |
| 实例回收 | 该实例的历史 Issue | 历史Issue保留只读，运行资源释放 |
| Body 离线超时 | 该 Body 上运行中的 Issue | Issue 标记"执行失败"，原因为"Body 离线超时"（见 ADR-016） |

### 关键规则

1. **Issue 是 Project 的协作记录，不随实例消失**——实例回收只释放运行资源，Issue 数据保留
2. **实例停止不可逆地影响运行中 Issue**——用户停止实例前需要明确后果
3. **Soul 更新不阻断使用**——Major 更新待确认期间，旧版本实例仍可接收新 Issue
4. **Project 归档是终态操作**——需要所有 Issue 处于终态才允许归档

### Phase 1 约束

- 不做 Issue 挂起恢复——实例停止后 Issue 直接失败，用户手动重试
- 不做跨 Project 联动——每个 Project 独立

## 被拒绝的替代方案

1. **实例停止时 Issue 挂起，重启后恢复**——被拒绝因为挂起恢复需要 Body 支持断点续执行，Phase 1 复杂度过高。

2. **实例回收时 Issue 一并清除**——被拒绝因为 Issue 是 Project 的协作记录，应该随 Project 生命周期而非实例生命周期。

## 后果

### 正面

- 联动规则明确，每个状态变更的后果可预期
- Issue 作为 Project 级资产，不受实例生命周期影响
- 用户停止实例前可以明确知道影响范围

### 负面

- 实例停止导致 Issue 失败可能让用户不满。缓解：停止前二次确认弹窗，明确告知影响
- Project 归档要求所有 Issue 终态，可能导致归档受阻。缓解：提供批量取消 Issue 的能力

## 复审条件

- 当需要支持 Issue 挂起恢复时（Phase 2）
- 当跨 Project 联动需求出现时
