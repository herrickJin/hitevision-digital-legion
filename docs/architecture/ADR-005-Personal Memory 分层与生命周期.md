# ADR-005：Personal Memory 分层与生命周期

## 上下文

PRD 定义 Personal Memory 为"Project Member 的个人偏好、通知偏好和个人关注记录"。PRD 假设 Personal Memory 归属于 Project Member（项目内个人身份），不跨项目共享，信心度 6/10。但 Project 定位为业务项目（ADR-004），有归档终态。这导致项目归档后个人偏好如何处理的问题。

## 决策

**Personal Memory 拆分为两层：通用偏好和项目特定偏好。**

### 分层定义

| 层级 | 归属 | 生命周期 | 示例 |
|------|------|----------|------|
| 通用偏好 | 平台用户身份（跨项目） | 持久存在 | "结果用中文展示"、"通知用邮件" |
| 项目特定偏好 | Project Member（项目内） | 随项目归档清理 | "这个项目用 React"、"关注登录模块" |

### 数据模型

```
PersonalMemory {
  user_id: string         // 平台用户 ID
  project_id: string|null // null = 通用偏好，非 null = 项目特定偏好
  key: string             // 偏好键
  value: string           // 偏好值
  source: enum            // manual（用户手动配置）| auto（系统自动学习）
}
```

### 生命周期规则

1. 项目归档时，该项目的所有项目特定偏好被清理
2. 通用偏好不受项目归档影响
3. 新项目创建时，自动加载用户的通用偏好
4. Phase 1 不做自动学习（source 统一为 manual），P1 考虑自动推断

### Phase 1 简化

- 数据模型上预留 project_id 字段，区分通用和项目级
- Phase 1 可以先只实现通用偏好层，项目特定偏好作为可选扩展
- 不影响 Personal Memory 不参与 RAG 检索的决策（ADR-008）

## 被拒绝的替代方案

1. **全部跟随项目归档**——简单但用户每进新项目都要重新配置。对通用偏好体验差。

2. **全部归属于平台用户身份**——Personal Memory 完全跨项目。被拒绝因为项目特定偏好（如技术栈选择）跨项目可能导致误导。

3. **不区分层级**——所有偏好统一存，项目归档时逐条判断保留还是清理。被拒绝因为判断逻辑复杂且不可靠。

## 后果

### 正面

- 用户通用偏好跨项目保留，不用重复配置
- 项目特定偏好随项目归档清理，不污染其他项目
- 数据模型预留扩展空间

### 负面

- 增加 Personal Memory 的数据模型复杂度（需要 project_id 区分）
- Phase 1 需要明确哪些偏好属于通用、哪些属于项目级

## 复审条件

- 当试点用户反馈偏好迁移需求时
- 当 P1 引入自动偏好学习时
