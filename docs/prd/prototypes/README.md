# 数字员工原型清单

> 本文件是 `docs/prd/prototypes/` 目录下所有数字员工原型的总览索引。

---

## 目的

这份清单回答三个问题：

1. 当前已定义了哪些数字员工原型。
2. 每个原型解决什么问题、处于协作链路哪个位置。
3. 第一批原型组合起来是否足以支撑最小项目协作闭环。

## 按协作链路分类

### 需求定义层

| 原型 | 作用 |
|------|------|
| 产品经理 | 把模糊需求转成结构化方案和任务输入 |

### 技术设计层

| 原型 | 作用 |
|------|------|
| 架构师 | 把产品需求转成技术边界、系统结构和接口约束 |

### 工程实现层

| 原型 | 作用 |
|------|------|
| 前端研发 | 前端页面、状态、交互和联调承接 |
| 后端研发 | 服务、接口、数据流和异常处理承接 |

### 质量验证层

| 原型 | 作用 |
|------|------|
| 测试工程师 | 测试范围、用例、风险和回归验证 |

> 项目协同层（状态整理、风险跟踪、依赖协调、项目汇报）由人类项目负责人承担，当前不设数字 PMO 角色。

## 闭环能力评估

第一批原型已形成最小项目协作闭环：

```
产品经理 → 架构师 → 前端研发 / 后端研发 → 测试工程师
```

覆盖：需求收敛 → 技术方案 → 工程承接 → 质量验证。

这意味着第一批原型已具备验证 `Project → 数字员工实例 → Issue` 主链路的条件。

---

## 当前边界与缺口

1. 没有独立的设计类数字员工。
2. 没有独立的运维/运行时类数字员工。
3. 没有独立的数据分析/运营类数字员工。
4. 没有定义多数字员工自动协作协议。
5. 没有数字化的项目协同角色。

v1.0 适用于内部产研项目协作场景，不适合直接外推为完整企业岗位体系。

---

## 扩展建议

下一批建议按以下顺序扩展：

1. 设计师数字员工
2. 运维/SRE 数字员工
3. 数据分析数字员工
4. 运营数字员工
5. 项目助理 PMO 数字员工（待项目协同需求明确后评估）

扩展原则：一人一档，全部继承通用模板，必须显式定义职责边界和测试用例。
