# 数字军团OS - 角色工作台原型设计规格

## 1. 项目概述

### 1.1 项目名称
数字军团OS - 角色工作台与Issue协作中心原型

### 1.2 设计目标
基于PRD-100和PRD-103产品需求文档，设计数字军团OS的核心交互界面：
- **角色工作台**：不同数字员工角色的差异化工作面
- **Issue协作中心**：任务创建、执行、状态管理、结果交付

### 1.3 核心设计原则
1. **角色差异化**：不同数字员工角色拥有不同的模块组合和布局
2. **任务驱动**：工作台模块响应Issue状态变化，实现联动
3. **专业工作面**：不是聊天页，而是角色化的专业工作区
4. **过程可追踪**：任务执行过程可视化，结果正式交付


#### 4.2.2 状态展示
1. **执行中**：展示时间线、工具调用、阶段产物
2. **等待补充信息**：高亮缺失字段，提供输入入口
3. **已完成**：展示最终结果、摘要、引用材料
4. **执行失败**：展示失败原因、重试按钮（retry_count < 3）
5. **已拒绝**：展示拒绝原因、推荐可接手角色

### 4.3 Issue状态机

#### 4.3.1 状态定义
```
待开始 → 执行中 → 已完成
    ↓       ↓
已拒绝   等待补充信息
    ↓       ↓
已取消   执行失败
```

#### 4.3.2 状态转换规则
- 待开始 → 执行中：人类确认后发起执行
- 待开始 → 已拒绝：启动前规划检查判定越界
- 待开始 → 已取消：Project Member主动取消
- 执行中 → 已完成：执行完成并产出结果
- 执行中 → 等待补充信息：发现关键信息不足
- 执行中 → 执行失败：执行异常（可重试，最多3次）
- 执行中 → 已拒绝：执行中发现真实边界越界
- 等待补充信息 → 执行中：人类补充信息后恢复

## 5. 工作台与Issue联动

### 5.1 联动事件

| 事件 | 触发时机 | 模块响应 |
|------|---------|---------|
| issue_created | Issue创建后 | 相关模块根据structured brief定位上下文 |
| issue_started | 数字员工开始执行 | 模块进入任务关联态，展示当前任务提示 |
| context_resolved | 系统识别到对象 | 模块自动定位到相关对象 |
| artifact_published | 阶段性产物生成 | 模块挂载产物并标记来源Issue |
| input_required | 需要用户补充信息 | 相关模块高亮缺失字段 |
| issue_completed | Issue完成 | 模块刷新最终状态并保留结果入口 |
| issue_failed | Issue失败 | 模块展示失败原因和可重试入口 |

### 5.2 典型联动场景

#### 场景1：产品经理草拟PRD
```
Issue创建 → 文档区创建草稿 → 需求池定位关联需求 → 知识上下文展示引用来源
```

#### 场景2：前端研发修改登录页
```
Issue创建 → 代码库定位相关文件 → 组件库定位登录组件 → 视觉走查挂载截图
```

#### 场景3：后端研发新增接口
```
Issue创建 → API定义定位接口 → 代码仓库定位服务文件 → 测试模块展示自测结果
```
