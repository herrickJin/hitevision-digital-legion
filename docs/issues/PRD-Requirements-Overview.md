### 1.2 需求边界说明

1. R2 是所有运行类需求的基础前置，不单独演化为项目管理产品。
2. R4 解决"如何工作"，R5 解决"如何承载任务状态"，两者必须联动但不可混同。
3. R6、R7、R8 是主链路底座能力；Phase 1 必须服务于单数字员工主链路，不独立扩张。
4. R9、R10 属于完整愿景保留项，不得反向挤占 Phase 1 P0 交付资源。

## 5. 排期优先级

### 5.1 第一梯队 — 立即排期

以下需求阻塞所有后续开发，必须第一批启动：

| 需求 | 理由 | 里程碑 | Issue 数量 | 状态 |
|------|------|--------|-----------|------|
| M0 方案对齐 | 全项目基础，对象模型/状态机/规范/技术选型 | M0 | 22 | ✅ 已拆 |
| R1 数字员工定义中心 | 原型是实例和工作台的前置依赖 | M1 | 27 | ✅ 已拆 |
| R2 Project 最小业务容器 | 实例必须归属 Project，Issue 必须归属 Project | — | 待拆 | ❌ |
| R8 AI 组织治理中心（基础层） | 权限/审计贯穿所有模块，需最早建立框架 | — | 待拆 | ❌ |

### 5.2 第二梯队 — 与第一梯队并行

| 需求 | 理由 | 说明 |
|------|------|------|
| R6 Wiki/Memory（基础层） | M1 定义中心的知识配置依赖 Wiki 基础能力 | 先做 R6.1 + R6.5 基础层 |

### 5.3 第三梯队 — M0 完成后启动

| 需求 | 理由 |
|------|------|
| R3 数字员工实例与多终端运行中心 | 依赖 R1（原型上架）+ R2（Project 容器） |
| R5 Issue 任务协作中心 | 依赖 R3（实例运行） |
| R4 角色工作台 | 依赖 R5（Issue 联动） |

### 5.4 第四梯队 — 主链路跑通后

| 需求 | 理由 |
|------|------|
| R7 工作流接入中心 | 需 Issue 执行链路先稳定 |
| R9 多数字员工协同编排中心 | P1，Phase 2 主能力 |
| R10 鸿合软硬件联动能力 | P2，仅预留接口边界 |
